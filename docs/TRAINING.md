# 训练报告

[简体中文](TRAINING.md) | [English](TRAINING_EN.md)

本文件记录发布模型的结构、训练配方、评估协议和限制。所有数字都来自本地实测。

---

## 1. 模型结构

发布模型是 **5.61M** 的动作打分 Q 网络：

```text
状态 (132) ─► MLP(512) ─┐
历史 (15×33) ─► LSTM(256) ─┴─► z (512)
动作 ID + 13 维特征 ─► embedding + MLP(128) ─┐
                                            ├─► Q(s,a)
z ──────────────────────────────────────────┘
```

- 三个座位共享主干 + 身份 one-hot；
- 动作空间 **26,064 + PASS**，按点数/链长/带牌规范化，不区分花色；
- 牌用 54-bit mask 表示；
- adapter：`z = z + adapter(z)`，adapter 为 512→1024→512 残差 MLP，最后一层零初始化；初始函数与 v2 完全等价。

### 动作空间

- 纯三张：3n；
- 三带一：4n；
- 三带二：5n；
- 飞机/飞机带单/飞机带对；
- 顺子、连对、四带二、炸弹、王炸、单张、对子；
- 共 26,064 个 rank 规范动作，最后一个动作是 PASS。

### 状态特征

自己手牌、三家已出牌、底牌、剩余张数、上一手、PASS 数、地主/农民身份、历史 15 步动作与玩家。  
对手手牌不进入网络；分析/评估时只做 determinization 采样。

## 2. 训练配方

### 2.1 阶段

| 阶段 | 内容 | 局数 |
|---|---|---:|
| v1 oracle | oracle 地主 + 对手池 | 82.9 万 |
| v1 随机分布 | 随机地主微调 | 124 万 |
| v2 续训 | 2048 并行；oracle 15% + 随机 85%；pool 30% + bot 10% | 656 万 |
| adapter | v2 + 1.05M adapter；低学习率继续 | 133 万 |
| 不洗牌专家 | 从 adapter 继续；不洗牌发牌 | 131 万 |

常规总训练量约 **996 万局**；不洗牌专家另加 **131 万局**。

### 2.2 关键超参数

- 并行环境：2048；
- 每轮 16,384 局，768 个梯度步；
- batch 2048；
- 学习率：v2 8e-5→4e-5；adapter 4e-5→2e-5；
- epsilon：0.05→0.02 / 0.03→0.015；
- 对手池 30%，启发式 bot 10%；
- oracle 地主 15%，随机 85%；
- 3 检查点 soup。

### 2.3 不洗牌发牌

公开规则只说“上一局不洗牌、切牌、按顺序发 17/17/17+3”；本地实现：

1. 首局随机；
2. 按实际出牌顺序记录每一手，保留组内结构；
3. 局末接三家剩余手牌（各自按点数排序）；
4. 随机切牌；
5. 连续取三份 17 张，随机分给三个座位；最后 3 张底牌。

本地实测约 **1.6 个炸弹/手**，普通随机约 0.06。  
这是可复现的本地近似，不是官方内部实现的逐字节复刻。

## 3. 评估

### 3.1 协议

- 常规：1024 副固定发牌，模型分别坐 3 个座位；每模式 2048–3072 局。
- 单座：模型一个座位，另外两家 bot；农民时队友也是 bot。
- 整方：地主一人或两个农民全由模型控制。
- oracle 地主：bid net 给三家 17 张牌打分，最高者当地主。
- 不洗牌：256 个不洗牌牌局；每局模型分别坐 3 个座位，共 768 局。
- 不洗牌头对头：同样 256 个牌局，整方地主/农民互换，512 局，无 bot。

### 3.2 常规结果

| 对手 | 总胜率 | 地主 | 农民 |
|---|---:|---:|---:|
| 随机 | 0.958 | 0.973 | 0.951 |
| 贪心 | 0.814 | 0.814 | 0.813 |
| 启发式（单座） | 0.657 | 0.768 | 0.602 |
| 启发式（整方） | 0.770 | 0.767 | 0.772 |
| 启发式 + oracle 地主 | 0.578 | 0.908 | 0.413 |

### 3.3 不洗牌结果

| 模型 | 总胜率 | 地主 | 农民 |
|---|---:|---:|---:|
| 常规 adapter | 0.5625 | 0.4375 | 0.6250 |
| **不洗牌专家** | **0.6549** | **0.5898** | **0.6875** |

整方头对头：常规 0.3613 vs 专家 **0.6387**。

### 3.4 延迟

5.61M，预热后 32 局：

```text
首个结果 p50  94ms  p99 136ms
64 样本  p50 593ms  p99 672ms
128 样本 p50 797ms  p99 875ms
512 样本 p50 1625ms p99 1792ms
1200ms 内 128 样本：32/32
```

“1.2s 内 99% 最优”是工程目标：先给可用 top-3，再继续加深；不是博弈论最优证明。

## 4. 复现

```powershell
# 默认小规模自对弈
python -m doudizhu.train --config configs/default.yaml

# 从发布权重继续不洗牌专家
python -m doudizhu.train --config configs/noshuffle3_20261031.yaml ^
  --resume checkpoints/best_model.pt
```

评估：

```powershell
python scripts/final_eval.py --model checkpoints/best_model.pt --games 1024
python scripts/eval_oracle.py --model checkpoints/best_model.pt ^
  --bid-net checkpoints/bid_net.pt --games 512
python scripts/eval_noshuffle.py --deals 256
python scripts/head_noshuffle.py --deals 256
```

训练日志写到 `runs/`（已 gitignore）。发布的两个权重是推理用 state_dict，不含 optimizer。

## 5. 硬件与性能

- GPU：RTX 5070 Ti 16GB（Blackwell，CUDA 12.8）；
- 常规训练吞吐约 1,300–1,400 局/s；
- GPU 利用率约 10%–30%：自对弈发牌、规则和 Numba 引擎在 CPU，GPU 不是唯一瓶颈；
- 推理：512 样本 p99 约 1.8s；128 样本 p99 约 0.9s。

## 6. 局限与后续

- **没有人类评测**：所有胜率都是对 bot/模型，不是人类胜率。
- **不洗牌规则是本地近似**：官方没有公开完整实现。
- **没有搜索蒸馏**：把 512 样本搜索值蒸馏回 Q 网络是后续最值得做的方向。
- **没有真实叫地主/抢地主流程**：训练使用 oracle + 随机地主混合，GUI 的叫地主是建议而非完整三家竞叫。
- 只支持标准三人斗地主，不含癞子/天地癞子等平台变体。
